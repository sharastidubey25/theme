# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

FixPapa "Set 5" theme: a static multi-page marketing/shop site (IT repair, AMC, rental, refurbished devices). Plain HTML + CSS + vanilla JS. There is no build step, package manager, linter or test suite.

To preview, serve the folder over HTTP (needed for video and `?cat=` query handling), e.g. `python3 -m http.server 8000` and open `http://localhost:8000/index.html`.

## Architecture

**Page types and their asset stacks**
- `index.html` (homepage) — `style.css` + `refurb-shop.css`; scripts: GSAP 3.12.5 + ScrollTrigger (CDN), `refurb-data.js`, `main.js`, `fixpapa-story.js`. `main.js` must degrade gracefully when GSAP is missing (`hasGsap`) or `prefers-reduced-motion` is set (`reduce`).
- Inner pages (`about`, `contact`, `account`, `blogs`, `blog-post`, `faqs`, `brands`, `device-health`, `partner`, `pulse`, `sell-ewaste`, `open-box-deal`, `rental`, `rental-category`, `refurbished`, `refurbished-category`) — `style.css` + `inner.css` (shared `.ip-*` inner-page components, body class `ip`) + one page-specific `<page>.css`; script: `inner.js` (shared header, theme, reveal, lazy video, filters, rental plans, warranty checker).
- `repair.html` — standalone: `style.css` + `repair.css`, script `repair.js` (its own header/theme/reveal + booking modal; does not use `inner.css`/`inner.js`). The booking modal is 3 steps (device: category → brand → service type; issue & visit: description, address, date + slot; confirm: summary, mobile, OTP inline) plus a success screen. Brands, diagnosis prices and cities are sample data in `repair.js`; it runs on a demo mock (any 6-digit OTP) unless `window.FPBookingApi = { sendOtp(mobile), verifyAndBook(otp, booking) }` is defined before it loads.

**Shop listings** — `refurbished.html`, `rental-category.html` and `products.html` share one listing engine: `assets/js/shop-list.js` (`window.FPShopList(cfg)`: builds the filter sidebar into `#rflAccs`, checkbox facets with live counts, snapping numeric ranges, price range, sort listbox, pagination, chips, phone drawer, URL state, promo-video lightbox) + `assets/css/shop-list.css` (`rfl-*`). Each page passes a config: `refurb-list.js` (data from `refurb-data.js`), `rental-list.js` (data from `rental-data.js`, `window.FPRental`) and `products-list.js` (all products: `products-data.js` `window.FPProducts` new items + refurbished items, with a Condition facet; `?brand=HP` from the Brands page "Check products" buttons, matched case-insensitively, shows a brand banner via the engine's `onRender` hook, which also hides the AMC / installation promo tiles (`.rfl-tiles`) whenever any brand is selected; the footer Category links on every page open `products.html?cat=Laptop|Desktop|Printer|Server|Projector`, the live-site form `?category=Laptop` (plurals and any case) is mapped onto `cat`, and a single category sets the title and breadcrumb, e.g. "Shop Laptops" or "HP Printers").

**Rental** — `rental-category.html?cat=laptop|desktop|printer|projector&months=1|3|6|12` is the single page for every rental category: category tabs (plain links), rental-period switch (prices are per month for the chosen plan, `FPRental.monthly`), category-specific filters, and an "Add to Cart" button on each card: it adds a rental line to the shared cart (`rent: { months, monthly, base }`, price = monthly × months, MRP = 1-month price × months so the plan saving shows as the discount) and opens `cart.html`, so rentals go through checkout and payment like purchases. `rental.html` "Rent Now" buttons (`data-rent-cat`) link there and carry the chosen plan (`inner.js`). The homepage "… on Rent" tiles (`.rent3-card`) link there too. Desktop data mirrors the live fixpapa.com/rent-a-product/desktop catalogue (27 items: Lenovo/Dell/HP × Core i7/i5/i3 × 10th/8th/6th Gen, 8 GB / 256 GB, generated in `rental-data.js`); laptop data mirrors fixpapa.com/rent-a-product/laptop pages 1–2 (32 listings in live order, typos cleaned; `LAPTOPS` in `rental-data.js`). Both lists are reversed so "Newest" matches the live order, and their prices are sample tiers because the live pages show ₹0.00. Cards show the brand + device as the title ("Lenovo Laptop", like the live site) and a labelled spec table (`.rcl-specs`: icon, label such as Processor / RAM / Storage, value; labels and icons in `SPEC` in `rental-list.js`); the cart line name includes the specs so similar items stay distinguishable; the page ends with the live site's four-perk strip (`.rcl-perks`).

**My Account** — `account.html#profile|wallet|orders|wishlist|addresses|branches|sub-users|tickets|inventory|notifications|contact` (menu and fields mirror fixpapa.com/account/user-profile). Panels switch on the URL hash; Personal Data is read-only until "Edit profile", then validated and saved; firm/government accounts get a name field plus the Firm Branches and Sub Users menu items. Other panels are empty states until the backend exists. Demo data lives in `localStorage` key `fp-profile`; a backend plugs in via `window.FPAccountApi = { getProfile, updateProfile, updateAvatar, logout }` (`assets/js/account.js`). The header account icon and the phone menu link here on every page.

**FixPapa Pulse** — `pulse.html` mirrors pulse.fixpapa.com in the Set 5 theme (hero with the homepage `fpp-*` dashboard visual, demo video `assets/media/pulse-demo.mp4`, audiences, Windows/Mac pricing, 26 FAQs, contact form). Download menu and plan "Buy now" go through a mobile-OTP modal, then hand off to the official site (`window.FPPulseConfig = { downloads, checkoutUrl }`, `window.FPPulseApi = { sendOtp, verifyOtp, enquiry }`; demo accepts any 6-digit code). Every "Device Health", "FixPapa Pulse" and "Fleet Monitoring" link points here; `device-health.html` remains only for its warranty checker (Brands page "Warranty" links).

**Cart** — `cart.html` (step 1 of Cart → Checkout → Payment, `.ck-steps` stepper in `assets/css/cart.css`). `assets/js/cart.js` loads on every page: any product card's "Add to Cart" (`.card.product .add`) reads name, prices and art from the card, stores it in `localStorage` key `fp-cart` (`window.FPCart = { items, add, setQty, remove, clear, count, totals, inr, subscribe }`, max 10 per item) and opens `cart.html`; the header cart icon links there with a live count badge (badge and toast styles at the end of `style.css`). The cart page lists items with quantity controls and remove (with undo), payment details (subtotal at MRP, discount, grand total), phone sticky checkout bar and refurbished suggestions; it loads `refurb-data.js` and inlines the `bk-*` sprite so every card's art renders. "Proceed to Checkout" goes to `checkout.html`.

**Checkout** — `checkout.html` (step 2; `cart.css` + `checkout.css`, scripts `cart.js` then `assets/js/checkout.js`; redirects to the cart when it is empty). Numbered Shipping / Billing sections: selects list saved addresses and branches (hidden, with a dashed note, until one exists) (localStorage `fp-addresses`); "Add new address / branch" buttons open one address dialog (branch adds branch name + optional GSTIN), the "Same as shipping address" checkbox (on by default) mirrors the shipping choice and hides the billing picker. Your Order summary with a discount code (demo codes FIXPAPA10, FLAT500 unless `window.FPCheckoutApi = { applyCoupon(code, cart) }` is defined). "Continue to Pay" validates both addresses, saves `{ ship, bill, same, coupon }` to localStorage `fp-checkout` and goes to `payment.html`.

**Payment** — `payment.html` (step 3; `cart.css` + `checkout.css` + `payment.css`, scripts `cart.js` then `assets/js/payment.js`; back to the cart if it is empty, to checkout if no address is chosen). "Delivering to" summary with Change, payment methods (official logos in `assets/img/pay/`, sources in its `CREDITS.txt`): UPI (Google Pay / PhonePe / Paytm buttons or UPI ID), card (formatting, Luhn, expiry, CVV, brand logo in the field), net banking (popular banks + select) and cash on delivery (orders up to ₹50,000), order summary with the coupon from checkout. Processing overlay, then an order-placed panel (order ID, amount, method, expected delivery, address). Demo mock (UPI `fail@upi` or a card ending 0002 is declined) unless `window.FPPaymentApi = { pay(order) → { orderId } }` is defined; success keeps the order in localStorage `fp-orders`, clears the cart and the coupon.

**About** — `about.html` (content from fixpapa.com/about-us: intro, journey + numbers, mission, services linking to their pages, sustainability, founders, contact; `about.css`). The footer "About FixPapa" link points here on every page.

**Contact** — `contact.html` (content from fixpapa.com/contact-us: "Message us" form with Full name / Email Address / Mobile Number / message, Office / Email / Phone cards plus working hours, all taken from the live page's structured data: E-262 Jyothi Nagar, Lalkothi, Jaipur 302005, +91 86965 44448 customer care, +91 95888 41806 support, support@fixpapa.com, WhatsApp 919799044449, Mon–Sat 9:30–19:30; Google Maps embed, links to repair / FAQs / partner, the live four-perk strip; `contact.css`). `assets/js/contact.js` validates and submits the form: demo unless `window.FPContactApi = { send(message) }` is defined. The footer "Contact Us" link points here on every page.

**FAQs** — `faqs.html` (the 30 Q&As from fixpapa.com/faqs, two duplicates merged into 29, grouped under AMC / Service calls / Inventory / Technical support / General as plain `<details>` in the HTML, under the boxed photo hero `.ip-hero.fq-hero` (`support.jpg`, copy on the right), in a two-column `.fq-layout` (sticky category menu `.fq-side` + questions; the menu becomes a scrolling tab row on phones); `faqs.css`, `faqs.js` adds category tabs with `#amc|service|inventory|support|general` links, live search over questions and answers, and `#qN` deep links). The footer "FAQs" link points here on every page.

**Policy pages** — `anti-discrimination-policy.html`, `privacy-policy.html`, `terms-and-conditions.html`, `refund-and-returns-policy.html`, `cancellation-policy.html`, `shipping-policy.html` and `deletion-policy.html` (text verbatim from the matching fixpapa.com pages, including the live T&C's odd wording, since it is legal text; sub-sections such as 1.1 / 2.1 are `.pl-role` cards, `.pl-roles--3` for three, plain lists `.pl-list`, numbered `.pl-list--num` with nested `ul`; the T&C contents uses Roman numerals via `data-n` on each `.pl-toc a`; the shipping page has a four-step order journey `.pl-steps`; the deletion page's request buttons open an email with the subject "Data Deletion Request"): plain navy hero `.ip-hero.pl-hero`, two-column `.pl-layout` (sticky "On this page" `.pl-toc`, a scrolling tab row on phones + numbered `.pl-sec` cards), "raise a concern" box. `policy.css` (`pl-*`) and `policy.js` (highlights the current section in the contents) are generic so the other footer policies (rental; still a `#` link) can reuse them. **Blog** — `blogs.html` (featured latest post + card grid, topic chips `?cat=repair|buying|rental|business|green`, search) and `blog-post.html?slug=…` (article, share buttons, CTA, related posts; unknown slug shows a not-found state), both rendered by `blog.js` from `blog-data.js` (`window.FPBlog`). The six posts are SAMPLE content because the live fixpapa.com/blogs is empty ("Page 1 of 0"); replace them with real articles or a CMS feed. `blog.css`. The footer "Blogs" link points here on every page.

**Partner program** — `partner.html` (content from the live partner-program page). Every "Become a Partner / Freelancer" button (`data-join`) opens a dialog like the live site: partner → partner.fixpapa.com or the app; freelancer → the FixPapa Engineer app (Play Store / App Store). `partner.html#freelancer` opens the dialog directly (`assets/js/partner.js`). The header "Become a Partner" button, phone menu, mega-menu card and footer partner links point here on every page.

**Sell e-waste** — `sell-ewaste.html` (content and per-unit prices from fixpapa.com/sell-ewaste). Pick items (select/remove) → sticky bar with count and estimate → "Sell selected items" opens the pickup form with a quantity per item and live estimate → success with a request ID. Demo unless `window.FPEwasteApi = { submit(request) }` is defined (`assets/js/ewaste.js`). Every "Sell your e-waste" / "E-Waste Recycling" link points here.

**Shared design system** — `assets/css/style.css` holds all tokens (`--primary`, `--navy`, `--ink*`, radii, shadows, fonts Manrope/Inter/JetBrains Mono) and dark mode via `[data-theme="dark"]` overrides. Page CSS files build on these tokens rather than redefining them.

**Duplicated per-page markup** — each HTML file inlines its own copy of the header/topbar, mobile nav, footer, an SVG icon sprite (`<symbol id="i-…">`, referenced with `<use href="#i-…">`), and an inline `<head>` script that applies the saved theme before paint. Changes to nav, footer or icons must be applied to every HTML file.

**Header mega menu** — the primary nav (Home · Services ▾ · Shop ▾ · For Business ▾ · Book A Repair · Brands), its `.mm` dropdown panels (categories left, text cards right, no icons) and the grouped `.mn-group` phone menu are identical on every page except for the `active` item and homepage section links (`#amc` on index, `index.html#amc` elsewhere). Behaviour lives in `assets/js/megamenu.js`, loaded on all pages; styles are at the end of `style.css`.

**Theme toggle** — persisted in `localStorage` key `fp-theme` (`dark`/`light`), applied as `document.documentElement.dataset.theme`. `main.js`, `inner.js` and `repair.js` each implement the toggle and must keep using the same key.

**Refurbished catalogue** — `refurb-data.js` is the single data source, exposing `window.FPRefurb` (`cats`, `products`, `byCat`, `catOf`, `stats`, `card`, `inr`) and injecting the `rf-*` product-art SVG sprite. It must load before `main.js` (homepage section), `refurb-list.js` (the `refurbished.html` listing: filter sidebar with live counts, price range, sort, pagination, URL state like `?cat=laptops&brand=Dell&sort=lo`; RAM, storage and screen size are snapping range sliders, the other facets checkbox lists; facet values are parsed from each product's `specs`) and `refurb-category.js` (renders `refurbished-category.html?cat=laptops|desktops|printers|cctv|accessories`). Product list is sample data meant to be replaced by a live backend.

**Homepage data** — other homepage content (new products, brand list/logos, testimonials) is hard-coded in arrays at the top of `main.js` and rendered into the DOM. Brand logos live in `assets/img/brands/`.

**Media** — background/section videos use `data-src` + `preload="none"` and are lazy-loaded by JS; each has a `.jpg` poster of the same name in `assets/media/`. `fixpapa-story.js` builds the animated "In Action" ad story and `[data-fp-art]` illustrations around `fixpapa-story.mp4`. `assets/media/AI-PROMPTS.md` documents the technician-uniform spec (orange #F97316 polo, navy trousers) for generating new footage; credits are in the `CREDITS*.txt` files.

**AI assistant widget** — every page loads `assets/css/assistant.css` and the six scripts in `assets/js/assistant/` (order: service, mock-service, conversation, avatar, chat-ui, assistant) just before `</body>`. Avatar, chat UI, conversation state and the chat service are separate and only meet in `assistant.js`; the default service is a keyword **mock** (no AI). See `assets/js/assistant/README.md` for the backend API contract and `window.FPAssistantConfig`.

## Conventions

- **Cache busting**: assets are referenced with `?v=X.Y` query strings (e.g. `style.css?v=7.4`, `main.js?v=7.0`). Bump the version in every HTML file that references an asset when you change it. Versions currently differ between pages (index uses `style.css?v=7.4`, inner pages `?v=7.0`).
- JS files are IIFEs using local `$`/`$$` query helpers; no modules or globals except `window.FPRefurb`, `window.FPRental`, `window.FPProducts`, `window.FPShopList` and the assistant's `window.FPAssistant` namespace.
- CSS is written compactly (one rule per line, minified-style declarations); match that style.
